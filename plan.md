## 1. Project summary (what we are proving)

A UAV base station serves 3 traffic classes (Emergency, Important, Normal) and each time slot chooses bandwidth shares `b_k` and power shares `p_k`. A SAC policy with an **ensemble of critics** acts every slot (fast loop). Ensemble disagreement `U_t` estimates epistemic uncertainty. When `U_t` is high **or** the emergency queue is high (hybrid trigger), an **LLM arbiter** (slow loop, asynchronous, 200 ms to 2 s latency) is called. It returns a JSON that sets **bandwidth floors / power priority** with a TTL. A **safety layer** projects the SAC action into the valid region and falls back to a hard-coded safe policy if the LLM is late or invalid.

**Claims to test (map to the report's RQ1-RQ4):**

| ID | Claim | How it is tested |
|----|-------|------------------|
| A | Ensemble `U_t` rises under OOD and gives *early* warning | AUROC, precision/recall, detection lead time (Phase 5) |
| B | The LLM adds value beyond a simple rule-based shield | Compare against rule-shield, random-trigger, DR-SAC, Lagrangian SAC (Phases 7-9) |
| C | Hybrid trigger beats periodic / reactive / always-on at lower cost | Pareto plot: SOS violation vs LLM call rate (Phase 9) |
| D | Safety layer keeps the system safe when the LLM fails | Failure-injection sweep (Phase 9) |
| E | Real-time feasibility | Actor+ensemble inference time per slot < 5 ms; fast loop never blocks (Phase 8) |

## 4. Default parameters (put in `configs/default.yaml`; agent may calibrate and must log changes)

**Timing**

| Param | Value | Note |
|-------|-------|------|
| `slot_ms` (Δt) | 5 | One decision per slot |
| `episode_slots` | 2000 (10 s) | |
| `D_th` | 15 ms (= 3 slots) | Emergency delay threshold |
| `llm_latency_ms` nominal | lognormal, median 350 ms, 5th-95th pct about 200-800 ms | Replace with measured values in Phase 8 |
| `llm_timeout_ms` | 1000 | After this, response is discarded and fallback activates |
| Stress latency (Scenario S3) | 2000 ms median | |

**Channel (Al-Hourani urban A2G, f_c = 2 GHz)**

| Param | Value |
|-------|-------|
| `a`, `b` | 9.61, 0.16 |
| `eta_LoS`, `eta_NLoS` | 1 dB, 20 dB |
| UAV altitude H | 100 m, hovering (no trajectory control; document as a scope limit) |
| Users | 3 class groups at random ground radius in [50, 500] m; fixed per episode |
| LoS/NLoS state | sticky Markov chain per class, stay prob 0.98, stationary prob from `P_LoS(θ)` |
| Small-scale fading | Rician K = 10 dB (LoS), Rayleigh (NLoS), AR(1) correlation 0.9 across slots |
| Noise | -174 dBm/Hz + 7 dB noise figure |
| `B_max`, `P_max` | 10 MHz, 1 W (30 dBm) |
| Rate | `R_k = b_k * log2(1 + p_k * g_k / (N0 * b_k))`, `g_k = 10^(-PL/10) * |h|^2`. Single UAV, no inter-cell interference (document this simplification). |

**Traffic (fluid queue; `Q_k(t+1) = max(0, Q_k - R_k*Δt) + A_k`)**

| Class | Nominal mean arrival | Notes |
|-------|----------------------|-------|
| Emergency | about 0.5 Mbps (Poisson packets of 200 B) | Small, delay-critical |
| Important | about 8 Mbps | Video; target `R_target` = 6 Mbps |
| Normal | about 6 Mbps | Best effort |

**Calibration requirement:** adjust arrival means so the total nominal load is about 50-60% of the mean achievable capacity, and so that a 4x Emergency surge combined with +15 dB shadowing *can* push the system into violation if the allocation is poor. Log the calibration. Queue cap per class (e.g., 2 Mbit) with overflow counted as drops. Delay `D_k = Q_k / max(R_k, eps)`, clipped at 1 s.

**Observation (16-dim, normalized):** `log10(g_k)` scaled (3), `log1p(Q_k)` scaled (3), `D_k / D_th` clipped to [0,5] (3), battery fraction (1), fraction of Emergency violations in last W = 50 slots (1), previous action (6).

**Action:** actor outputs 6 values in [-1, 1]; env maps first 3 and last 3 via `softmax(3 * x)` to `b_k/B_max` and `p_k/P_max` (both sum to 1). The trajectory/MAC-weight items on slide 8 are **out of scope**; log this in the decision log.

**Reward:**
```
r_t = w_emg*r_emg + w_imp*r_imp + w_norm*r_norm - lambda_pen * 1[D_emg > D_th]
r_emg  = -clip(D_emg / D_th, 0, 5)^2
r_imp  = log(1 + min(R_imp / R_target, 1))
r_norm = R_norm / R_norm_ref          (R_norm_ref = nominal capacity share, so r_norm is about 0..1)
w = (1.0, 0.5, 0.1), lambda_pen = 5   (tune only in Phase 4, then freeze)
```
`eta_llm` (reward_weight_scale) is **removed**; see decision log D4.

**Trigger / safety defaults**

| Param | Value |
|-------|-------|
| `N_critics` | 10 (ablate 1, 2, 5, 10) |
| `tau_unc` | 99th percentile of `U_t` on in-distribution validation episodes (Phase 5) |
| `theta_queue` | Emergency queue equivalent to about 2 slots of drain at current rate; tune in Phase 7 |
| debounce | `U_t > tau` for m = 3 consecutive slots |
| cooldown | 50 slots (250 ms) |
| TTL of an LLM mask | 600 slots (3 s) |
| Fallback | Emergency bandwidth floor 0.8, Emergency power floor 0.8; lasts 200 slots, then returns to DRL unmasked unless re-triggered |
| Target LLM call rate | at most 5% of slots (report both calls/slot and mask-active fraction) |

### Phase 6: Safety layer (mask, projection, fallback), with no LLM yet (about 1 week)

**Agent tasks**
1. `control/mask.py`: `Mask` dataclass `{bw_floor[3], power_floor_emg, expires_at}` and `project(action_b, action_p, mask)`:
   ```
   b = f + (1 - sum(f)) * b_raw        # guarantees b >= f and sum(b) = 1, requires sum(f) <= 1
   p: same construction for the emergency power floor
   ```
   If `sum(f) > 1` or any value is out of range, reject the mask (treated as an invalid LLM output).
2. `control/fallback.py`: fixed safe allocation (Emergency 0.8 bandwidth and power, remainder split 0.6/0.4 between Important and Normal).
3. Train a variant with **random masks during training** (decision D5): `SAC-Mask-Aware`. Compare to the plain model evaluated with masks applied only at test time.
4. `baselines/rule_shield.py`: **Rule-Shield baseline (no LLM)**: if `Q_emg > theta_queue` for m slots then set a mask with Emergency floor 0.5 (+ power floor) for TTL slots; cooldown applies. Variants: zero latency, and with the same 350 ms delay as the LLM. Tune `theta_queue` on validation scenarios only.

**Tests (`test_mask.py`)** (property-based with random inputs)
- Output sums to 1; output >= floors; projection is idempotent; invalid masks are rejected; mask expiry is correct; budget constraints (sum b <= B_max, sum p <= P_max) hold in every env step over 10^5 random steps.

**Acceptance:** Rule-Shield reduces Emergency violation under surge and shadow relative to Pure SAC. Report by how much and what it costs in Important/Normal throughput. **This is the baseline the LLM must beat.**

### Phase 7: Hybrid controller with asynchronous (simulated-latency) LLM interface using MockLLM (about 1 week)

**Agent tasks**
1. `llm/schema.py` (pydantic):
   ```json
   {
     "operating_mode": "NORMAL|SOS_SURGE|DEEP_FADING|COMPOUND|UNKNOWN",
     "min_bandwidth_ratio": {"emergency": 0..1, "important": 0..1, "normal": 0..1},
     "power_boost_emergency": true|false,
     "ttl_duration_slots": 50..1000
   }
   ```
   Validator rules: all fields present, floors in [0,1], `sum(floors) <= 0.95`, `emergency <= 0.9`, TTL in range. Anything else is invalid. (`reward_weight_scale` removed, decision D4.)
2. `llm/mock.py`: `MockLLM` implements the same interface as the real client and returns a rule-based JSON from the prompt features (e.g., high `dQ_emg` and stable CSI gives `SOS_SURGE` with emergency floor 0.6). Supports **failure injection**: `p_invalid_json`, `p_out_of_range`, `p_wrong_diagnosis`, `p_timeout`, and latency distribution.
3. `control/hybrid_controller.py`: the per-slot loop (simulated time, not wall-clock):
   ```
   each slot t:
     1. apply responses with arrival_slot <= t: validate -> install Mask(expires_at = t + ttl);
        invalid or timed-out -> activate Fallback for fallback_slots
     2. a_raw = actor(s); U = ensemble_std(s, a_raw)
     3. a = project(a_raw, active_mask or fallback or None)
     4. s', info = env.step(a)
     5. trigger = debounce(U > tau) OR (Q_emg > theta_queue); if trigger and cooldown_ok:
            prompt = build_prompt(...); resp = llm.call(prompt)      # wall-clock call, can be slow
            L = sampled (or measured) latency in ms; arrival_slot = t + ceil(L / slot_ms)
            if L > timeout: schedule fallback at t + ceil(timeout/slot_ms), discard resp
            (variant "interim": apply Fallback immediately at trigger until response arrives)
     6. expire masks past expires_at (the DRL regains full control)
   ```
   The fast loop must **never** wait on the LLM. Count: calls, valid / invalid / timeouts, fraction of slots with mask active, fallback active.
4. Controller supports trigger modes: `uncertainty`, `queue`, `hybrid`, `periodic(K)`, `reactive` (fires only after the first violation), `always` (every slot, with MockLLM only), `random(rate)`.
5. `llm/prompt.py` (used later by the real LLM): structured prompt with the sliding-window (50 slots) mean/variance/slope of CSI per class, queue lengths and `dQ_emg`, `U_t`, trigger reason, current mask, constraints, and the output schema, plus 3 few-shot examples. **The prompt must never contain ground-truth scenario labels or the `ood_flag`.**

**Tests (`test_controller.py`, `test_schema.py`)**
- A response with latency 300 ms is applied exactly `ceil(300/5)` slots after the trigger.
- Timeout produces fallback and no mask.
- Budget constraints hold in all failure-injection modes.
- Cooldown is respected; the call rate is at most `1/cooldown`.
- Fast loop makes exactly one decision per slot even when latency is 2 s.

**Acceptance:** with MockLLM, the full pipeline runs end to end on all scenarios; the failure-injection sweep (0 / 10 / 30 / 100% failures) shows Emergency violations degrade toward the *Fallback-only* level but never crash and never violate the budget.

**Scenarios**

| ID | Scenario |
|----|----------|
| S0 | Nominal (sanity) |
| S1 | Traffic surge: Emergency arrivals 4x for 2 s (400 slots), start slot random in [500, 1200] |
| S2 | Deep shadowing: +15 dB for 400 slots |
| S3 | LLM API degradation: latency median 2 s (applied together with S1) |
| S4 | Compound: S1 + S2 + S3 |
| S5 | Unseen magnitude: surge 8x, shadow +25 dB |

**Protocol**
- 5 training seeds per learned method; 20 evaluation episodes per (method, scenario, seed) using fixed evaluation seeds disjoint from training seeds. Use bootstrap 95% CIs; paired tests (e.g., Wilcoxon) when claiming "better".
- `scripts/run_grid.py` runs the grid in resumable chunks and writes one tidy CSV (`results/final/metrics.csv`) with columns: method, scenario, seed, episode, and all metrics below.

## 8. Risks and fallbacks

| Risk | Mitigation |
|------|-----------|
| Pure SAC does not degrade under OOD | Strengthen scenarios; widen training/test gap; report honestly |
| Ensemble `U_t` does not detect OOD | Plan B in Phase 5; keep queue trigger as main; narrow the claim |
| Rule-Shield matches or beats LLM | Report it. Reposition contribution as "uncertainty-triggered safety shield"; emphasize cases where the LLM helps (compound, unseen) or where it does not |
| Training too slow on free Colab | Reduce steps, N critics to 5, G = 1; reduce eval episodes; use checkpoints and resume |
| Free LLM API rate limits | Cache aggressively; use local Ollama / Colab vLLM; fewer eval episodes for LLM methods; run MockLLM for sweeps and real LLM for key rows |
| LLM JSON invalid | Constrained decoding where available; validator + fallback is the designed behavior |
